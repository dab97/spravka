## Инварианты (проверять при КАЖДОЙ задаче)

1. **`documents.json` остаётся внешним и редактируемым в продакшене** — никаких статических
   импортов JSON в JS; загрузка только через `fetch('/data/documents.json')` с `cache: "no-cache"`
   и bust-параметром на повторной попытке (инвариант №1 из AGENTS.md). Касается особенно P1-6 и P2-1.
2. **Правила `.htaccess`** (no-cache для JSON) не пересматриваются.
3. Внешние ссылки — только нативные `<a>` (инвариант №2 из AGENTS.md); при разрезке `App.tsx` (P2-2, P2-4)
   не заворачивать их в роутер или обработчики.

## P1 — Дефекты поведения

### [x] P1-1. Вспышка не той темы при загрузке (FOUC) — `index.html` ✅ 2026-10-26
**Проблема:** в `index.html` нет inline-скрипта инициализации темы. Класс `dark` ставится только после
монтирования React и `useEffect` в `src/context/theme-provider.tsx:33` → пользователь с тёмной темой
видит белую вспышку при каждой загрузке.
**Фикс:** короткий блокирующий `<script>` в `<head>` **до** CSS: читает `localStorage`
(`spravka-ui-theme`) / `matchMedia('(prefers-color-scheme: dark)')` и ставит класс на `<html>`.
**Файл:** `index.html` (+ согласовать с `theme-provider.tsx`).
**Сделано:** скрипт в начале `<head>`; ключ синхронизирован через `THEME_STORAGE_KEY` в провайдере.

### [x] P1-2. Тема «system» не реагирует на смену системной темы ✅ 2026-10-26
**Проблема:** `theme-provider.tsx:38` читает `matchMedia` один раз, подписки на `change` нет.
Смена темы ОС не применяется до перезагрузки. Аналогично `ThemeSwitcher.tsx:23` — `isDark`
считается при рендере без подписки.
**Фикс:** подписка `matchMedia.addEventListener('change', ...)` в провайдере (для `system`);
`isDark` в свитчере брать из провайдера.
**Файлы:** `src/context/theme-provider.tsx`, `src/components/ThemeSwitcher.tsx`.
**Сделано:** `systemDark` в состоянии + подписка на `change`; в контексте появился `resolvedTheme`,
`ThemeSwitcher` использует его вместо собственного `matchMedia`.

### [x] P1-3. Мёртвая защита `useTheme` ✅ 2026-10-26
**Проблема:** `theme-provider.tsx:69` — проверка `context === undefined` никогда не срабатывает:
дефолт контекста — `initialState`. Использование без провайдера молча вернёт заглушку.
**Фикс:** `createContext<ThemeProviderState | null>(null)`, в хуке проверять `null` и бросать ошибку.
**Файл:** `src/context/theme-provider.tsx`.
**Сделано:** контекст типизирован `| null`, `useTheme` бросает ошибку при отсутствии провайдера.

### [x] P1-4. `key={index}` для категорий — `App.tsx:164` ✅ 2026-10-26
**Проблема:** `documents.json` редактируется на хостинге; при удалении/перестановке категории
React сматчует карточки не по тем позициям.
**Фикс:** `key={category.title}`.
**Файл:** `src/App.tsx`.
**Сделано:** key заменён на `category.title`; `id` для якорей остался индексным.

### [x] P1-5. Тултип «QR-код недоступен» недостижим — `document-card.tsx:70-91` ✅ 2026-10-26
**Проблема:** `TooltipTrigger` обёрнут вокруг `disabled`-кнопки — браузер не шлёт события наведения
на disabled-элементы, тултип никогда не показывается.
**Фикс:** заменить `disabled` на `aria-disabled` + стилизация `pointer-events-none` (или вынести
тултип на обёртку).
**Файл:** `src/components/document-card.tsx`.
**Сделано:** `disabled` → `aria-disabled` (+ комментарий почему); действие по-прежнему блокирует
`handleQrClick` (открывает модалку только при наличии ссылки); визуальное «недоступно» — прежние классы.

### [x] P1-6. Возможная двойная загрузка `documents.json` ✅ 2026-10-26
**Проблема:** preload в `index.html` с `crossorigin="anonymous"`, а `fetch()` в `App.tsx:37` —
с дефолтным режимом креденшелов. При несовпадении браузер отбрасывает preload
(warning «not used because request credentials mode does not match»).
**Действие:** проверить консоль devtools при сборке/preview; если warning есть — синхронизировать режимы.
**Файлы:** `index.html`, `src/App.tsx`.
**Сделано:** эмпирическая проверка на `npm run preview` (vite 6) через браузер: `documents.json`
загружается **ровно один раз**, initiatorType=`link` — preload матчится с `fetch()` и потребляется им.
Проблемы нет, код не менялся. На проде стоит один раз перепроверить в реальных devtools
(другой сервер/`.htaccess`), но по семантике (`crossorigin="anonymous"` ↔ `credentials: "same-origin"`) всё совпадает.

## Чего делать НЕ стоит

Не тащить роутер, state-менеджер, react-query — один экран и один `fetch`;
килобайты и сложность без выгоды.

## Порядок работ

1. **P1-1 … P1-5** — дефекты, независимы, компактны (~1 ч).
2. **P1-6** — проверить в devtools (нужен запущенный dev/preview).
