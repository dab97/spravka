# Architecture.md — данные, алгоритмы, хранилище

Техническая документация для агентов и разработчиков. Обзор проекта — [AGENTS.md](AGENTS.md), дизайн — [Design.md](Design.md).

## Поток импорта

`ImportDialog` → `onImport` → `store.setApplicants`:

1. **Парсинг** (`lib/csv-parser.ts`, `parseExcelOrCSV`): CSV читается как текст, XLS/XLSX — через SheetJS. Формат (budget/paid) определяется по заголовкам: «Состояние договора»/«Оплачено» → paid, «Согласие» → budget, иначе — по имени файла («внебюджет», «платн»…). Заголовок ищется по строке с «ФИО» (+«№» слева); для paid-формата позиции колонций резолвятся по заголовкам. Направление — из имени файла (`getProgramIdFromFileNameOrString`). Ячейки типизированы `CellValue`.
2. **Слияние** файлов между собой: по `fullName`/applicantId — объединение `priorities`, максимум баллов, пер-program scores (`programScores[programId]`), контракт/оплата через «лучшее» значение.
3. **Сортировка приоритетов**: `priorities` сортируются по `programScores[pid].priorityRank`, затем применяются ручные правила из `stores/priority-overrides.ts`.
4. **Отказы**: файл отказов матчится по `uniqueCode` (точно) либо `normalizeName(ФИО)`; совпавшим ставится `hasRefusal: true`, `hasConsent: false`, дата/примечание.
5. **Стор**: `setApplicants` определяет режим (`inferMode` по наличию `fundingType === 'paid'`), пересчитывает конкурсные списки и персистит срез. **Каждый импорт полностью заменяет данные режима** — без файла отказов старые флаги `hasRefusal` не переносятся.

## Алгоритм конкурсных списков (`generateCompetitionLists`, lib/admissions.ts)

- **Активные участники**: бюджет — `!hasRefusal && hasConsent`; платное — `!hasRefusal && не зачислен на бюджет` (по `uniqueCode` из `loadEnrolledCodes()`, `lib/orders.ts`, архив `public/orders/manifest.json`).
- **Опция `requirePayment`** (страница «Зачисление по факту оплаты», `PaidFactLists`): место может занять только оплативший (`paid === true`) — распределение то же, но зачисление = факт оплаты. Договор без оплаты место не занимает (`factStatus = 'awaiting'`), оплативший вне мест — `'outside'` (возврат). Расчёт независим: страница сама вызывает `generateCompetitionLists` с этой опцией, как FinancePage — без неё; стор и финансы не затрагиваются.
- **Матчинг**: итеративное стабильное распределение (до `programs.length × 3` проходов). Для каждой программы кандидаты = активные с `priorities.includes(programId)`, прошедшие минимальные баллы предметов (`MIN_SUBJECT_SCORES`), и для кого эта программа лучше текущей по `priorityRank`. Сортировка: totalScore → subjectsSum → баллы трёх предметов → ФИО. Топ-N зачисляется: бюджет — `places`, платное — `paidPlaces ?? ∞`.
- **Статусы**: `admitted` (зачислен сюда), `admitted_elsewhere` (зачислен на лучшую программу), `rejected` (не прошёл / отказ / нет согласия на бюджете). Полный список программы включает всех подавшихся, отсортированных по рейтингу.
- **Ключ матчинга — `fullName`** (не id/код): однофамильцы-тёзки схлопнутся в одного абитуриента.

## Финансовая модель (FinancePage)

Страница сама вызывает `generateCompetitionLists(paidApplicants, programs, 'paid', excludedCodes)`; в бюджетном режиме данные берутся из IDB-среза `admissions-paid` (стopр хранит только активный режим). Цена семестра = цена года ÷ 2 (цены — `localStorage['finance-prices-per-year']`, редактируются в Настройках).

- **План** = `paidPlaces` × цена семестра.
- **Собрано** = зачисленные (`admitted`) с `paid === true` × цена семестра направления зачисления.
- **Ожидается** = `admitted` + договор подписан + не оплачен.
- **К возврату** = `paid === true`, но не зачислен ни на одно платное направление. Причина: «Отказ» (`hasRefusal`) / «Зачислен на бюджет» (код в `excludedCodes`) / «Ниже порога». Сумма — цена семестра первого приоритета (`priorities[0]`).
- «Поступило на счёт» = Собрано + К возврат. % плана = Собрано / План. Возвраты временны: при сдвиге списков человек может попасть в план.

## Хранилище

| Ключ | Где | Что |
|---|---|---|
| `admissions-budget` / `admissions-paid` | IndexedDB (`lib/idb-storage.ts`) | Срезы режимов: `{ state: { applicants, programs, competitionLists, importedAt, dataAsOf, refusalsAsOf }, version: SCHEMA_VERSION=5 }` |
| `admissions-programs` | IndexedDB | Общие настройки направлений (места) |
| `admissions-mode` | localStorage | Активный режим |
| `finance-prices-per-year` | localStorage | Цены за год |
| `admissions-theme` | localStorage | Тема |

Рехайдрация стора (`onRehydrateStorage`): миграция из localStorage → загрузка программ → загрузка среза режима → пересчёт списков. Бюджетный режим дополнительно подтягивает архив зачисленных (`loadArchivedBudgetApplicants`) и обновляет ФИО по кодам из платного среза.

## Таймстемпы актуальности

- `importedAt` — момент импорта.
- `dataAsOf` — максимум `lastModified` файлов списков (дата выгрузки), fallback — момент импорта.
- `refusalsAsOf` — дата файла отказов либо `null`.
- Хранятся раздельно по режимам. UI: правый нижний угол hero-баннера Dashboard, две строки; тултип — время импорта.

## Производительность (Общий список абитуриентов как эталон)

- **Никаких `.find()` по конкурсным спискам в рендере** — это O(N×M); вместо этого Map `admittedByName` (ФИО → программа) через `useMemo`.
- Строки таблицы — `React.memo`-компонент `StudentRow` со стабильными пропсами (`useCallback`-хендлеры, мемо-карты): открытие шторки не перерисовывает таблицу (проверено — 0 рендеров строк).
- Первый рендер таблицы гейтится двойным `requestAnimationFrame` (`tableReady`) — браузер успевает закрасить скелетон до тяжёлого коммита.
- Шторка карточки — `modal={false}` + ручная блокировка скролла: модальный Radix ставит `inert` на фон (таблица ~10k DOM-узлов → сотни мс). Оверлей затемнения в `ui/sheet.tsx` — собственный div в портале перед контентом (Radix-оверлей в non-modal не рендерится).

## Грабли и неочевидности

1. `Applicant.program` содержит **имя файла**, не programId. Привязка — `priorities[]` / `programScores`.
2. Матчинг использует `programScores[pid].priorityRank`, а НЕ порядок массива `priorities` (после импорта они синхронны, но оверрайды меняют только массив).
3. Ручные оверрайды приоритетов (`priority-overrides.ts`) влияют на сортировку `priorities` и, соответственно, на привязку возвратов в финансах, но НЕ на матчинг.
4. xlsx: эпоха дат — `workbook.Workbook?.WBProps?.date1904` (не `Date1904`).
5. Архив приказов лежит в `src/public/orders/` (Vite `publicDir: 'src/public'` — не перепутать с корневым `public/`); без него страница приказов пуста и бюджетники не исключаются из платного конкурса.
6. Пустые `catch`-блоки намеренно содержат комментарии — правило `no-empty`.
